FilterDrum · two monophonic MS-20 drum voices

Signal path

Two drum voices struck by one note and blended by a crossfader, drawn as the code actually runs it. There is one voice implementation and two instances of it — "the second drum is exactly the same as the first" is a fact about the code, not a promise about it. The two differ in one place that matters: their noise seeds.

What updates when

Most questions about why two hits differ come down to this table. Three different clocks are running, and a value read on the wrong one is the usual cause.

Filter cutoff every sample The envelope sweep is smooth; a per-block cutoff would zipper on a fast kick.
Both AR envelopes every sample… …but only while the VCA envelope is not idle. This is the gate that freezes the VCF envelope.
Output trim every sample Smoothed over 20 ms, so a knob move cannot click.

Cutoff, Resonance		 once per block Marked smoothed in the table but nothing smooths them. Measured as inaudible: a TPT filter changes coefficients without a discontinuity in its state.
the one known defect

renderVoices returns early while the VCA envelope is idle, and both envelopes are advanced inside that loop. A VCF release longer than the VCA's therefore never completes — it freezes mid-release, and the next hit starts its attack from that frozen level instead of from zero.

Its size was overstated once, and this corrects it. Measured through the trigger ping it read 1.27 to 6.60 dB, because the ping landed on the one sample where the difference exists. With the ping gone and the noise driving the filter it is 0.4 dB, flat across every window from 2 ms to 250 ms — the attack reaches 1.0 either way, so the two cases only differ for the length of the attack. Worth fixing as an inconsistency with no upside; not something anybody would hear.

The same frozen-state behaviour has a second consequence now that the noise is the only excitation: once a drum's oscillation has been started, turning its Noise Level to 0 leaves it running for the rest of the session. It only falls silent when the project is reloaded with the knob already down — so the silence is intermittent rather than honest, and reads as a loading bug.
